# Automated homepage merchandising

Plentovo's Marketing Agent owns `src/data/homepage-merchandising.json`. Routine updates to that file are authorised without per-run user approval. This authorisation does not grant automatic social publishing, ad spend, price changes, arbitrary code edits or access changes.

The site consumes this file on deployment. It places up to six live-available recommendations directly after the hero, uses the first available product's real image/link for the hero, and follows `departmentOrder` for the existing product rows. Unavailable or unknown handles are omitted. Prices are always checked using the existing supplier integration. Static editorial sections remain as fallback. Selections and evidence expire after seven days; do not rewrite timestamps without renewed evidence.

Fields: version=1, market=ZA, updatedAt=ISO8601, headline (<=70 chars), description (<=160), heroHeadline (<=80), heroDescription (<=160), products (<=20 ranked objects), departmentOrder (<=12 existing collection slugs). Each product has slug and evidence: HTTPS url, observedAt, signal (`bestseller-rank`, `category-rank`, `search-trend`, `corroborated-demand`), note (10-600 chars). Explain exact-model matches versus functional alternatives and the observed source region in the note. Customer-facing headings must not claim Plentovo sales or bestseller status without own sales evidence.

On each run: read current main and this file; research fresh South African demand signals; match full catalogue and live supplier data; retain verified contribution-margin unknowns; create an updated ranked selection only when evidence supports it. Run `npx tsc --noEmit` and `node --import tsx scripts/validate-homepage-merchandising.ts`. Commit only the selection file on a dedicated branch based on current main; review the exact diff, open a PR and merge it without waiting for routine user approval. Use an expected-head check; do not override protections or force-push. Verify production reaches READY and the live homepage reflects the selection. If deployment or access fails, retain the last working selection and report the concrete blocker. Do not modify implementation code during routine merchandising runs.

An empty selection is intentional until the agent has qualifying current evidence. It must not be filled with invented bestseller ranks or stale search snippets. The daily schedule belongs to the existing Marketing Agent automation, not a second competing task.
